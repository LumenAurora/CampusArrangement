## 1. 基本约定

### 1.1 请求规范

| 项目 | 说明 |
|------|------|
| **协议** | HTTP（生产环境建议 HTTPS） |
| **Content-Type** | `application/json` |
| **字符编码** | UTF-8 |
| **时间格式** | ISO8601（如 `2026-05-29T08:00:00+08:00`） |

### 1.2 认证方式

所有需要认证的接口都需要在请求头中携带 JWT Token：

```
Authorization: Bearer <token>
```

**Token 获取方式:**
- 调用登录接口 `/auth/login` 获取 Token
- Token 有效期为 24 小时
- Token 过期后需要重新登录

### 1.3 响应规范

**成功响应:**

```json
{
  "code": 200,
  "message": "success",
  "data": { ... }
}
```

**错误响应:**

```json
{
  "detail": "错误信息"
}
```

### 1.4 HTTP 状态码

| 状态码 | 说明 | 使用场景 |
|--------|------|---------|
| `200` | 成功 | 请求成功处理 |
| `201` | 已创建 | 资源创建成功 |
| `400` | 请求错误 | 参数校验失败、业务规则违反 |
| `401` | 未认证 | Token 缺失或无效 |
| `403` | 权限不足 | 用户无权执行该操作 |
| `404` | 未找到 | 请求的资源不存在 |
| `409` | 冲突 | 资源冲突（如名额已满） |
| `422` | 数据验证错误 | 请求体格式错误 |
| `500` | 服务器错误 | 服务器内部错误 |

## 2. 认证接口

### 2.1 用户登录

**接口:** `POST /auth/login`

**描述:** 用户登录并获取 JWT Token

**请求体:**

```json
{
  "username": "admin",
  "password": "admin"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `username` | string | ✅ | 用户名 |
| `password` | string | ✅ | 密码 |

**成功响应 (200):**

```json
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": {
    "id": "u1",
    "username": "admin",
    "role": "super_admin",
    "created_at": "2026-05-01T00:00:00"
  }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `token` | string | JWT Token，有效期 24 小时 |
| `user.id` | string | 用户 ID |
| `user.username` | string | 用户名 |
| `user.role` | string | 用户角色 |
| `user.created_at` | string | 注册时间 |

**错误响应:**

| 状态码 | 说明 |
|--------|------|
| `400` | 用户名或密码为空 |
| `401` | 用户名或密码错误 |

**cURL 示例:**

```bash
curl -X POST http://127.0.0.1:8000/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username": "admin", "password": "admin"}'
```

---


**成功响应 (200):**

```json
}
```

**错误响应:**

| 状态码 | 说明 |
|--------|------|
| `401` | Token 无效或已过期 |

## 5. 报名接口

**接口:** `POST /registrations`

**描述:** 用户提交报名

**权限:** 已登录用户

**请求体:**

```json
{
  "activity_id": "a1",
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `activity_id` | string | ✅ | 活动 ID |
| `slot_id` | string | ✅ | 时段 ID |
| `priority` | int | ✅ | 志愿优先级（1-3） |

**成功响应 (201):**

```json
{
  "id": "r1",
  "user_id": "u1",
  "activity_id": "a1",
  "slot_id": "s1",
  "priority": 1,
  "status": "confirmed",
  "created_at": "2026-05-29T10:00:00"
}
```

**错误响应:**

| 状态码 | 说明 |
|--------|------|
| `400` | 参数校验失败 |
| `401` | 未认证 |
| `404` | 活动或时段不存在 |
| `409` | 名额已满（实时模式）或已报名 |

**说明:**
- 实时模式下会先锁定时段名额，失败会返回容量不足错误

## 8. 错误处理

### 8.1 错误响应格式

```json
{
  "detail": "错误信息"
}
```

### 8.2 常见错误码

| HTTP 状态码 | 错误类型 | 说明 |
|------------|---------|------|
| `400` | Bad Request | 请求参数错误或业务规则违反 |
| `401` | Unauthorized | 未认证或 Token 无效 |
| `403` | Forbidden | 权限不足 |
| `404` | Not Found | 资源不存在 |
| `409` | Conflict | 资源冲突（如名额已满） |
| `422` | Unprocessable Entity | 数据验证失败 |
| `500` | Internal Server Error | 服务器内部错误 |

### 8.3 错误处理示例

```python
from fastapi import HTTPException

# 参数校验失败
if not activity_id:
    raise HTTPException(status_code=400, detail="活动 ID 不能为空")

# 资源不存在
activity = db.get_activity(activity_id)
if not activity:
    raise HTTPException(status_code=404, detail="活动不存在")

# 权限不足
if current_user.role not in ["super_admin", "organizer"]:
    raise HTTPException(status_code=403, detail="权限不足")

# 业务规则违反
if slot.used_count >= slot.capacity:
    raise HTTPException(status_code=409, detail="名额已满")
```

## 9. 接口实现建议

### 9.1 架构原则

| 原则 | 说明 |
|------|------|
| **分层调用** | 统一从应用层调用领域服务，不要在路由层直接写业务判断 |
| **字段稳定** | 所有返回值尽量保持字段稳定，避免客户端 RemoteService 频繁改动 |
| **错误明确** | 排班和报名接口应保留明确的失败信息，便于 UI 直接展示 |

### 9.2 代码示例

```python
from fastapi import FastAPI, HTTPException, Depends
from app.application.activity_service import ActivityService
from app.infrastructure.auth import get_current_user

app = FastAPI()

@app.post("/activities")
async def create_activity(
    activity_data: ActivityCreate,
    current_user: User = Depends(get_current_user)
):
    """
    创建活动
    
    1. 验证权限
    2. 调用应用服务
    3. 返回结果
    """
    # 验证权限
    if current_user.role not in ["super_admin", "organizer"]:
        raise HTTPException(status_code=403, detail="权限不足")
    
    # 调用应用服务
    activity_service = ActivityService()
    try:
        activity = activity_service.create_activity(
            name=activity_data.name,
            owner_id=current_user.id,
            signup_start=activity_data.signup_start,
            signup_end=activity_data.signup_end,
            details=activity_data.details,
            signup_mode=activity_data.signup_mode,
            allocation_mode=activity_data.allocation_mode
        )
    except ValueError as e:
        raise HTTPException(status_code=400, detail=str(e))
    
    return activity
```

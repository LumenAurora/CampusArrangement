# 后端接口文档

## 1. 基本约定
- 协议：HTTP + JSON
- 服务：FastAPI
- 默认地址：`http://127.0.0.1:8000`
- 认证方式：`Authorization: Bearer <token>`

## 2. 通用返回规范
- 成功：返回 JSON 对象或数组
- 失败：返回 `{"detail": "错误信息"}`
- 认证失败：HTTP 401
- 权限不足：HTTP 403
- 参数或业务校验失败：HTTP 400
- 资源不存在：HTTP 404

## 3. 认证接口

### 3.1 登录
- 方法：`POST /auth/login`
- 请求体：
```json
{
  "username": "admin",
  "password": "admin"
}
```
- 响应体：
```json
{
  "token": "xxxxxxxxxxxxxxxx",
  "user": {
    "id": "u1",
    "username": "admin",
    "role": "super_admin"
  }
}
```

## 4. 用户接口

### 4.1 获取用户列表
- 方法：`GET /users`
- 权限：超级管理员、组织者

### 4.2 创建用户
- 方法：`POST /users`
- 权限：超级管理员
- 请求体：
```json
{
  "username": "user01",
  "password": "123456",
  "role": "user"
}
```
- 响应体：
```json
{
  "id": "u2",
  "username": "user01",
  "role": "user"
}
```

## 5. 活动接口

### 5.1 获取活动列表
- 方法：`GET /activities`
- 权限：已登录用户

### 5.2 获取活动详情
- 方法：`GET /activities/{activity_id}`
- 权限：已登录用户

### 5.3 创建活动
- 方法：`POST /activities`
- 权限：超级管理员、组织者
- 请求体：
```json
{
  "name": "志愿服务",
  "signup_start": "2026-05-29T08:00:00+08:00",
  "signup_end": "2026-05-30T18:00:00+08:00",
  "details": "活动说明",
  "signup_mode": "realtime",
  "allocation_mode": "greedy"
}
```

### 5.4 获取活动时段列表
- 方法：`GET /activities/{activity_id}/slots`
- 权限：已登录用户

### 5.5 新增活动时段
- 方法：`POST /activities/{activity_id}/slots`
- 权限：超级管理员、组织者
- 请求体：
```json
{
  "start_time": "2026-05-31T09:00:00+08:00",
  "end_time": "2026-05-31T12:00:00+08:00",
  "capacity": 30
}
```

## 6. 报名接口

### 6.1 提交报名
- 方法：`POST /registrations`
- 权限：已登录用户
- 请求体：
```json
{
  "activity_id": "a1",
  "slot_id": "s1",
  "priority": 1
}
```
- 说明：实时模式下会先锁定时段名额，失败会返回容量不足错误

## 7. 排班接口

### 7.1 执行排班
- 方法：`POST /scheduling/run`
- 权限：超级管理员、组织者
- 请求体：
```json
{
  "activity_id": "a1"
}
```
- 响应体：
```json
{
  "count": 12
}
```

## 8. 现有客户端预留但后端尚未实现的接口
当前远程仓储已经预留了以下接口，建议后续补齐，否则远程模式的统计和结果页会不完整：

- `GET /metrics/overview`
- `GET /metrics/users/{user_id}`
- `GET /schedules?activity_id=...`
- `GET /schedules?user_id=...`

## 9. 接口实现建议
- 统一从应用层调用领域服务，不要在路由层直接写业务判断
- 所有返回值尽量保持字段稳定，避免客户端 RemoteService 频繁改动
- 排班和报名接口应保留明确的失败信息，便于 UI 直接展示
